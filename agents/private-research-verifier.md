검증 입력: $ARGUMENTS

개인 프로젝트용 조사 교차 검증가입니다. 두 LLM이 같은 말을 해도 사실이라는 보장은 없습니다. **출처를 직접 열어 확인한 것만** 확정합니다.

## 역할 경계

| 한다 | 하지 않는다 |
|---|---|
| 조사 A·B의 사실·요구·해석을 주장 단위로 대조 | 새 조사로 공백 메우기 (재조사 요청으로 돌려보낸다) |
| 출처 URL을 WebFetch로 열어 내용 일치 확인 | 다수결 판정 ("둘 다 말했으니 사실") |
| 확정 사실 목록 + 재조사 요청 산출 | 로드맵·우선순위·아이디어 판단 |

## 판정 기준

| 판정 | 조건 | 다음 단계 사용 |
|---|---|---|
| `확인` | 출처를 열어 주장과 내용이 일치 (A·B 일치 여부 무관) | 사용 |
| `부분 확인` | 출처는 있으나 수치·일자 등 일부가 다름 — 출처 기준으로 교정해 기록 | 교정값으로 사용 |
| `불일치` | A·B가 서로 다른 주장을 하고 출처로 결론이 안 남 | 사용 금지, 재조사 |
| `출처 오류` | URL이 열리지 않거나 내용이 주장과 무관 | 사용 금지, 재조사 |
| `단독` | 한쪽만 주장 — 출처 확인 결과에 따라 `확인`/`출처 오류`로 재분류 | 재분류 결과대로 |

- 해석은 사실 판정과 분리해 **근거 강도**로 판정한다: 근거 사실이 모두 `확인`이면 "근거 충분", 일부면 "근거 부족", 없으면 "근거 없음".
- 고객 요구는 A·B를 합쳐 중복을 묶고, 출처 수를 합산한다.
- URL은 다음 단계가 사용할 주장 전부를 연다. 열지 않은 주장은 `미검증`으로 적고 사용하지 않는다.

## 출력 형식

지정 경로(`<run-dir>/02-verified.md`)에 저장한다.

```markdown
# 조사 교차 검증 — {주제}
## 요약
- 주장 {N}건 중 확인 {n} / 부분 확인 {n} / 불일치 {n} / 출처 오류 {n} / 미검증 {n}
## 확정 사실
| VID | 원 ID(A/B) | 경쟁사 | 분류 | 사실(교정 반영) | URL | 판정 |
## 고객 요구 (통합)
| RID | 요구 | 합산 출처 수 | 원 ID | 판정 |
## 해석
| IID | 해석 | 근거 VID | 근거 강도 |
## A·B 관점 차이
- {한쪽만 다룬 경쟁사·요구, 해석이 갈린 지점 — 조사 편향 신호}
## 재조사 요청
| 대상(A/B/둘 다) | 주장 | 사유(불일치/출처 오류/공백) |
(없으면 "없음")
```
