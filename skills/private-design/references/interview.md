# 인터뷰 — 쉬운 질문을 디자인 결정으로 번역

사용자는 디자인 용어를 모른다. 질문은 생활 언어로 하고, 번역은 스킬이 한다.

## 질문 규칙

- AskUserQuestion 으로 묻는다. 한 번에 **최대 3문항**, 문항마다 선택지 2~4개를 둔다. "잘 모르겠어요(알아서)" 는 자동 제공되는 "Other" 로 받아도 된다.
- 선택지에 디자인 용어를 쓰지 않는다. "미니멀" ✗ → "꼭 필요한 것만 보이게" ✓.
- 이미 답이 나온 것은 다시 묻지 않는다. 요청 문장·PRD·기존 `tokens.json` 을 먼저 읽는다.

## 질문 은행

| 묻는 것 | 질문 예 | 선택지 예 |
|---|---|---|
| 사용자·상황 | 누가, 언제 주로 쓰나요? | 출퇴근길에 폰으로 잠깐 / 책상에서 오래 / 밤에 누워서 |
| 느낌 | 쓰는 사람이 어떤 기분이면 좋겠어요? | 믿음직하고 차분하게 / 가볍고 재밌게 / 빠르고 효율적으로 |
| 참고 앱 | 써 본 앱 중 느낌이 좋았던 게 있나요? | 토스 / 당근 / 노션 / 배민 |
| 정보량 | 한 화면에 얼마나 보여 줄까요? | 하나씩 크게 / 적당히 / 한눈에 많이 |
| 핵심 행동 | 이 화면에서 꼭 해야 하는 일 하나는? | (자유 입력 — 화면마다 다름) |
| 싫은 것 | 이런 건 싫다 하는 게 있나요? | 너무 화려함 / 글자가 작음 / 버튼이 많음 |

## 번역표 — 답 → 디자인 결정

| 답 | 결정 |
|---|---|
| 폰으로 잠깐 | 큰 터치 영역(44px 이상), 한 화면 한 과업, 하단 고정 CTA(주요 버튼 1개) |
| 책상에서 오래 | 정보 밀도 중간 이상, 표·목록 허용, 본문 15~16px |
| 밤에 누워서 | 다크 모드를 먼저 다듬기, 순백(#FFF) 배경 대신 살짝 어두운 배경 |
| 믿음직·차분 | 채도 낮은 파랑·남색 accent, 넉넉한 여백, 모서리 8~12px |
| 가볍고 재밌게 | 채도 높은 accent, 큰 모서리(16px 이상), 일러스트·이모지 허용 |
| 빠르고 효율적 | 여백 좁게, 회색 위계 촘촘히, 아이콘+짧은 라벨 |
| 하나씩 크게 | 큰 제목(24px 이상), 화면당 정보 묶음 1~2개 |
| 한눈에 많이 | 카드·목록 밀도 높게, 보조 글자(text-secondary) 적극 사용 |
| 참고 앱 지정 | 그 앱의 패턴을 기준으로 한다. 화면마다 참고한 패턴을 1줄 적는다 |
| 답 없음·알아서 | 토스 패턴 (단순한 위계, 한 화면 한 과업, 단일 CTA, accent 1곳, 넉넉한 여백) |

## 인터뷰 요약 (다음 단계 입력)

인터뷰가 끝나면 아래 형식으로 요약해 사용자에게 1회 보여 주고, 시안 단계의 입력으로 쓴다.

```
- 누가·언제: …
- 원하는 느낌: …
- 참고: …
- 피할 것: …
→ 시안 방향 2~3개: A(…), B(…), C(…)
```

시안 방향은 서로 **확실히 달라야** 고를 수 있다. 같은 레이아웃에 색만 조금 다른 시안 3개는 비교가 안 된다.
