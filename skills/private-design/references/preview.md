# 시안 — HTML로 렌더링해 고르게 하기

사용자는 토큰 표를 읽고 판단할 수 없다. 결정이 필요한 모든 지점에서 실제 화면처럼 보이는 HTML 을 보여 준다.

## 발행 방식

- **Artifact 로 발행한다.** 작성 전에 `artifact-design` 스킬을 로드한다 (Artifact 도구 규약). 발행된 페이지는 비공개가 기본이다.
- 시안 1회 = HTML 파일 1개 = Artifact 1개. 같은 라운드의 수정은 **같은 파일 경로로 재발행**해 링크를 유지한다.
- 작업 파일은 스크래치패드에 둔다. 사용자가 최종 선택한 시안만 `{카테고리}/design/previews/` 에 복사한다.

## 페이지 구성

| 요소 | 규칙 |
|---|---|
| 시안 개수 | 2~3개. 같은 내용을 서로 다른 방향으로 그린다 |
| 배치 | 휴대폰 폭(375px) 프레임을 나란히 둔다. 좁은 화면에서는 세로로 쌓는다 |
| 라벨 | 시안마다 쉬운 말 이름 + 한 줄 설명. 예: "A · 차분한 파랑 — 여백이 넉넉하고 버튼이 하나예요" |
| 라이트/다크 | 시안마다 두 모드를 **동시에** 보여 준다 (프레임 2개 또는 토글). 한 모드만 있는 시안은 보여 주지 않는다 |
| 내용 | 실제 같은 예시 문구·숫자를 쓴다 ("Lorem ipsum" 금지). 빈 상태·오류 상태가 중요한 화면이면 그 상태도 1개 그린다 |
| 하단 안내 | "마음에 드는 시안 번호, 또는 '1번 배치에 2번 색'처럼 섞어서 말해 주세요. '답답해'·'너무 튀어' 같은 느낌도 좋아요." |

## 색은 토큰으로만

- 시안의 색은 전부 CSS 변수로 정의한다. 시안마다 `[data-variant="a"]` 범위에 라이트 값을, `[data-variant="a"][data-theme="dark"]` 범위에 다크 값을 둔다.
- 변수 이름은 [private-fe-convention](../../../rules/private-fe-convention.md) 의 시맨틱 토큰을 쓴다: `--background`, `--surface`, `--text-primary`, `--text-secondary`, `--border`, `--accent`, `--danger`.
- 변수 정의 밖에 색을 직접 쓰지 않는다. 그래야 고른 시안의 변수를 그대로 `tokens.json` 으로 옮길 수 있다.

## 보여 주기 전 검사 (필수)

1. 시안별 토큰을 임시 `tokens.json` 으로 뽑아 `design_check.py tokens` 를 돌린다. 대비 미달 시안은 고쳐서 다시 검사한다.
2. HTML 파일에 `design_check.py source` 를 돌린다. 변수 정의 밖의 하드코딩 색이 0건이어야 한다.
3. 두 검사 exit 0 을 확인한 뒤에 발행한다. 검사 raw 출력은 완료 보고에 첨부한다.

## 피드백 라운드

- 사용자 답을 받아 고친 시안을 다시 발행한다. 고른 방향 1개를 다듬거나, 섞은 조합 1~2개를 새로 만든다.
- 라운드마다 "무엇을 바꿨는지"를 쉬운 말 1~3줄로 알려 준다. 예: "글자를 한 단계 키우고, 버튼을 화면 아래에 붙였어요."
- **3라운드**가 지나도 정해지지 않으면, 지금까지 고른 요소를 요약하고 "이대로 확정할까요?"를 묻는다. 무한히 반복하지 않는다.
