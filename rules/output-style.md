# 출력 스타일 가이드

## 문체

- 대화 응답은 해요체(~합니다)를 사용합니다.
- 핵심부터 씁니다. 한 문장에 하나의 정보만 담습니다.
- 표와 불릿을 우선 사용합니다. 산문체는 최소화합니다.

## 문서 문체 (PRD·로드맵·과제 목록·게시 문서)

사람이 읽는 산출 문서는 사내 PO PRD 톤을 따릅니다 — 보기 쉽고 간결하게.

- 개조식 명사형 종결: "~필요", "~불가", "~로 변경", "= 없음". 서술형 "~합니다"는 쓰지 않습니다.
- 압축 기호: `=`(값·정의), `→`(전환·결과), As-Is / To-Be 표.
- 변경 태그 `NEW` / `UPDATE` / `DELETE` / `KEEP`, 우선순위 태그 `P1` / `P2`.
- 예외·주의는 굵은 한 줄 + 하위 불릿.
- 내부 근거 ID(조사·검증 ID 등)는 본문에 섞지 않고 섹션 끝 `근거:` 한 줄로 모읍니다.
- 근거 추적용 중간 산출물(조사·검증·아이디어 원문)은 이 규칙의 예외입니다.
- 구조 기준: [private-prd-template](./private-prd-template.md)

## 구체성

- 추상적 표현을 금지합니다. 수치로 표현합니다.
  - "여러 곳" → "3곳"
  - "많은 API" → "12개 API"
  - "느린 응답" → "P95 2.3초"

## 코드 참조 형식

- 메서드 참조: `파일경로#메서드명`
- 라인 참조: `파일경로:42`
- 예시: `AlertService.kt#trigger`, `V20260401__add_column.sql:15`

## 약어 규칙

- 약어는 첫 등장 시 풀네임을 병기합니다.
  - 예: "TDD(Technical Design Document)"
- 두 번째부터는 약어만 사용합니다.

## 용어 원칙

- 도메인 개념은 영문을 유지합니다: Alert, Symbol, Portfolio, Rental
- 프로세스/동작은 자연스러운 한국어를 사용합니다: 다운그레이드, 배포, 롤백, 전환
- 상태값은 한글로 표기합니다: 완료, 실패, 부분 실패, 진행 중, 대기 (enum 이름은 영문 유지, 설명만 한글)
- 기술 용어도 자연스럽게 한글화합니다:

| 원문 | 한글 |
|------|------|
| fire-and-forget | 결과 미추적 |
| 4-phase | 4단계 그룹 병렬 |
| blue-green | 블루그린 배포 |
| shadow traffic | 섀도 트래픽 |
| dual write | 이중 기록 |
| strangler fig | 점진적 대체 |
